# Memory plugin audit

Date: 2026-09-09. Baseline: upstream `@dsh-external/dsh-memory@0.2.11`, commit [`a7d67948336e32663f99468bbdb1194fcb99111c`](https://github.com/haitang1/dsh-memory/tree/a7d67948336e32663f99468bbdb1194fcb99111c). Fork: [DigiStrique-Solutions/dsh-memory](https://github.com/DigiStrique-Solutions/dsh-memory). This report covers the unmodified runtime; it does not claim the findings are fixed.

## Decision

The project is a useful source base, but should not yet be the foundation for unattended procedural learning. Fix access control, shared-writer behavior, canonical record integrity, revocation, and background-job lifecycle first. Documentation and a mostly green unit suite overstated the evidence supporting the earlier recommendation.

The most consequential security finding is an unauthenticated settings route exposing a configured embedding key and accepting configuration changes. Its impact depends on who can reach the Host port. The audit did not install this plugin into a live profile or establish that any deployed system has been exploited.

## Findings

Priority P1 means address before deployment/learning. P2 means a correctness or capability limitation that belongs in the implementation work. There is no asserted P0 emergency.

### F01. P1: settings route has no authentication and returns the API key

**Evidence:** [`lib/web.js:75-90`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/web.js#L75), lines 99-129 and 139-145; `lib/client.js:469-472`. `memorySettingsSnapshot` returns full `value`, `base`, and `user` settings. GET requires no credential or origin. POST checks Origin/Fetch Metadata but no authenticated identity. A direct HTTP client can forge those headers. A password input masks display, not the JSON response or DOM value.

**Reachability and impact:** any client able to reach this exact Host route can read a configured embedding key and, with a matching revision, change settings such as the outbound embedding destination and summarization behavior. A later vector search sends stored content to the configured endpoint. The local DSH [WebServer dispatch](https://github.com/deepseek-ai/deepseek-harness/blob/5dda764ed3aa172535a7967b06ff95d9cbfe536a/packages/host/webserver/src/index.ts#L222) calls exact handlers directly; the server is not an authentication wrapper. An external authenticating reverse proxy may restrict reachability, but this plugin does not enforce it. No live exploit was attempted.

**Proof:** fixture GET with empty headers returns 200 and a synthetic key; POST without credentials but a matching Host/Origin calls `settings.replace` and returns 200.

**Fix and acceptance:** require the deployment's authenticated principal and configuration capability on both operations; keep CSRF checks separately. Store a credential reference and return only configured/not-configured metadata. Test unauthenticated GET/POST, forged Origin, unauthorized principal, revision conflicts, and absence of synthetic keys in response layers, logs, and Client state.

### F02. P1: live lock can be stolen, and its old owner can delete the replacement

**Evidence:** [`lib/store.js:778-813`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L778). Staleness depends only on file mtime exceeding 60 seconds. There is no heartbeat or live-owner check. Release unlinks the pathname without verifying owner identity and leaves the instance writable.

**Impact:** a second profile or process started after 60 seconds can believe it owns the same store while the first continues writing. Old-owner disposal can remove the new owner's lock. Per-instance promise queues cannot prevent lost updates across those writers.

**Proof:** two live store instances both report ownership after aging only the lock timestamp; releasing the first removes the second's lock.

**Fix and acceptance:** choose one authoritative Host writer and reject other writers, or use a reviewed cross-process locking/transaction design with owner identity and conservative recovery. Never steal a lease by age alone. Verify actual competing processes, owner crash, PID reuse, stale-release identity, and recovery. Do not claim the in-process DSH domain queue solves cross-process access.

### F03. P1: raw Markdown cannot safely represent arbitrary memory content

**Evidence:** [`lib/store.js:108-137`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L108), `validateContent` at 332-336. Any body line beginning `### ` starts a new record; `**id:**`, tags, and importance lines are interpreted as metadata wherever they occur. Serialization writes content verbatim.

**Impact:** model-supplied facts, imported notes, or a legitimate Markdown procedure can create phantom records, alter interpreted identifiers/importance, and make original records difficult to update. This is a data-integrity and memory-poisoning surface, not demonstrated code execution.

**Proof:** one accepted content string round-trips into two records, one with an attacker-selected synthetic id.

**Fix and acceptance:** structured schema-validated canonical records, stable ids independent of body text, Markdown only as a projection/export. Test arbitrary headings, metadata-looking prose, code fences, blank lines, duplicate ids, and malformed legacy imports. Quarantine ambiguous legacy entries rather than silently guessing their intended structure.

### F04. P1: archived facts remain retrievable but cannot be corrected or forgotten

**Evidence:** [`lib/store.js:899-922`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L899), search at 968-975. Update/delete inspect only active entries. Search, review, duplicate detection, and export also read archives.

**Impact:** once automatic archiving moves a wrong fact, tools return its id but cannot correct or remove it. It remains available to future retrieval and export. This makes revocation unsuitable as the control for a learning system.

**Proof:** force archiving with a small budget, retrieve the old fact, then both update and delete return `no entry`.

**Fix and acceptance:** mutation by stable id across storage tiers; durable tombstones/revisions applied to search, summaries, embeddings, exports, and reimports. Distinguish recall revocation from full historical erasure. Verify an archived fact is correctable and that a revoked fact cannot return through rollback or pending consolidation.

### F06. P1: truncation acknowledges facts the model never received

**Evidence:** [`lib/store.js:366-389`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L366), [`lib/index.js:554-577`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/index.js#L554), 586-596 and 626-634. Input truncates journal/rollout text to byte slices, but success commits `snapshot.maxSeq` and all selected rollout block counts.

**Impact:** under backlog, omitted additions/corrections/deletions are marked consumed. A deleted fact already in the summary may persist without its deletion ever being presented. Separately, turn extraction truncates to the first 40 KB while recording the last observed sequence (`index.js:146-158,528`), so later material can also be skipped.

**Proof:** bounded input omits a trailing deletion. Source trace establishes that the caller commits the entire snapshot cursor. The complete model-driven loss scenario was not executed with a real model.

**Fix and acceptance:** select complete records within budget and return the exact included ids/revisions; acknowledge only those after durable publication. Persist remaining work and prioritize corrections/revocations. Verify a backlog larger than the budget drains fully, with no skipped deletion or truncated evidence marked consumed.

### F07. P1: standalone MCP bypasses the shared-writer lock

**Evidence:** [`bin/dsh-memory-mcp.mjs:47-58`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/bin/dsh-memory-mcp.mjs#L47), 219-237. It creates writable `MemoryStore` instances but never acquires the Host lock. Default storage overlaps the Host default. `withLock` only serializes one instance.

**Impact:** concurrent MCP/Host clients can overwrite raw files or race journal sequence assignment even before the F02 lease issue. MCP also has no configured equivalent of Host read-only scopes.

**Proof:** a spawned MCP fixture adds and updates a fact while another store holds the directory lock.

**Fix and acceptance:** route MCP through the same authoritative service/policy or use separate explicitly owned stores with import/export. Until then deny writes when another owner exists. Run multi-process write, cancellation, restart, schema validation, and scope-policy parity tests.

### F08. P1: secret protection does not cover mutation and output paths

**Evidence:** [`lib/index.js:831-835`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/index.js#L831) checks add, but update at 880-886 and import at 1180-1190 do not. Summary read at 794, search snippets at 990, review/export/browser return content without redaction. MCP update/read/search likewise return raw values. Summarization/embedding calls receive text without a shared secret policy.

**Impact:** content rejected by add can enter through update, import, seeding, or automated summaries and be returned to models, exports, or configured remote providers. The tool-controlled `allowSecret` boolean is not a trusted authorization decision. Best-effort regex scanning is also not comprehensive secret detection.

**Proof:** MCP with redaction enabled accepts a synthetic `sk-` credential through update and returns/persists it. The detector recognizes that same string.

**Fix and acceptance:** enforce common ingress and egress policy through the service; credential references use `ctx.credentials`; sanitize before persistence and provider calls. Scan output/rendered text, data, logs, history, exported artifacts, and error paths. Remove model-granted bypass and document any deliberate operator-controlled retention policy.

### F10. P1: unload releases ownership before background work has stopped

**Evidence:** [`lib/index.js:443-488`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/index.js#L443), 524-529, 735-750. LLM calls get a timeout controller independent of the plugin lifecycle. Disposal aborts a different controller, clears accounting, and releases the lock without awaiting work. After an awaited LLM call, rollout publication does not recheck lifecycle cancellation.

**Impact:** a removed/reloaded plugin can continue spending tokens and writing memories after ownership is released. The new generation may then race the old one. Captured service references and disposers also need review for child dependency withdrawal.

**Proof:** a gated fake LLM stream remains un-aborted after disposal; resolving it writes a rollout afterward using the real plugin code and BlockAssembler.

**Fix and acceptance:** combine lifetime, request, and deadline signals; track and await jobs; recheck cancellation/version immediately before publication; release ownership last. Register effects on the dependency-owning child Context. Verify unload, service withdrawal, reload, abort during I/O, and no late writes/provider calls.

### F12. P1: file tools grant unconstrained Host filesystem effects

**Evidence:** [`lib/index.js:1129-1144`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/index.js#L1129), 1172-1179, 1388-1416. Model-selected directories go through Host `resolve`, `mkdir`, `readFile`, and `writeFile`, with no session-root resolution, provider containment, no-follow handling, or post-check cancellation. Export writes use a check-then-write pattern and follow existing file symlinks.

**Impact:** if the deployment grants these tools, it also grants writes outside the agent's confined workspace to the fixed export/browser filenames, and reads through a selected `raw_memories.md` path. A preexisting symlink plus overwrite can redirect a write. This is not arbitrary filename selection or a claim that generic tool pre-execute denial can be bypassed; the defect is the excessive authority of the allowed tool body.

**Verification:** source traced; no live filesystem escape exercised. Add a temporary-root symlink/provider-denial fixture during hardening.

**Fix and acceptance:** use the caller's filesystem capability and explicit export destination authorization; deny unsupported enforcement, symlinks, special files, stale overwrite selections, and oversized imports. Internal store I/O belongs to its dedicated root, not an unrestricted model path.

### F05. P2: restart loses the fingerprints that protect AGENTS synchronization

**Evidence:** [`lib/store.js:993-1010`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L993), `index.js:716-723,1520-1542`. State writes persist `agentsMdFingerprint` and `seededSummaryFingerprint`, but reads discard both. Startup initializes new baselines when they are absent.

**Impact:** after restart the conflict detector can bless a manually edited summary as an untouched baseline. A later source change may overwrite it. Source changes made while stopped can also be silently adopted as the baseline without being synchronized.

**Proof:** write/read drops both fingerprint fields.

**Fix and acceptance:** versioned state schema preserving validated fields; migration test spanning restart with changes to source, summary, or both. No conflict baseline should be recreated from an edited state without an explicit recovery decision.

### F11. P2: vector retrieval bypasses its tag filter

**Evidence:** [`lib/store.js:619-654`](https://github.com/haitang1/dsh-memory/blob/a7d67948336e32663f99468bbdb1194fcb99111c/lib/store.js#L619). The first pass filters tags; the final vector pass searches the original unfiltered entries and appends them.

**Impact:** `vector:true` returns records excluded by requested tags. Tags are not currently an authorization boundary, so this is a filtering bug rather than a demonstrated cross-scope security bypass.

**Proof:** the same query returns zero results with a disjoint tag filter and lexical retrieval, but one excluded result when local vectors are enabled.

**Fix and acceptance:** apply all allowed-scope and tag filters before any ranking/provider request; verify lexical, local-vector, and remote-vector parity.

## Additional confirmed limitations and implementation risks

- **F09, policy limitation:** `readOnlyScopes` is documented as blocking write tools only. It does not prevent summarization or consolidation. The fixture demonstrates background LLM work under `['*']`. This is not a contradiction of the documented type comment, but it is unsuitable as the only policy for unattended learning. Introduce separately named capture, mutation, publication, and egress policies, enforced on every path.
- **Freshness:** add/update/delete change raw/journal data, not the injected summary. They request an LLM merge which can be skipped for missing route, failure, or the 10-minute consolidation interval. There is no timer ensuring skipped work runs later. The README's next-step visibility description is therefore too strong. Revoke immediately in retrieval and rebuild derived summaries from versioned facts.
- **Replacement import:** `merge:false` clears only the active raw file and emits only additions. Archives and old derived summary facts are not tombstoned. Define replace versus append versus restore precisely and make replacement a recoverable mutation.
- **Project scope:** automatic rollouts/injection select workspace scope; explicit project-store writes do not enter that injected workspace summary. Disabling scoped memory silently redirects explicit workspace/project requests to global. Invalid scope strings normalize to undefined. Select one explicit scope policy and reject unavailable/invalid scope instead of broadening it.
- **Rollback and concurrency:** rollback only targets global summary. It neither rolls back canonical facts nor marks a revision revoked. Consolidation lacks a freshness check against rollback/sync while its LLM call is in flight. A safe revision-pointer model must specify what rollback restores and which revocations remain effective.
- **Resource limits:** archive and journal reads are unbounded; duplicate review is quadratic; remote embeddings send all filtered active and archived text per search. There is no built-in embedding deadline, response cap, dimension/finite-number validation, or tool signal forwarded to `requestEmbeddings`. MCP readline and pending requests lack transport bounds. Add quotas and real deadlines; local private embedding services should require an explicit allowed destination rather than being categorically forbidden.
- **Evidence quality:** turn extraction flattens user/assistant text without preserving role/source attribution or tool outcomes. Session cursors are in-memory and pruned, so resumed sessions can summarize already consumed history. Queue saturation drops work rather than recording pending work. These are material gaps for procedural learning, even where acceptable for best-effort notes.
- **CI and release:** the Host smoke catches any import exception and skips, potentially hiding incompatible exports. CI installs no peers. `check-release.mjs` ignores child test exit status and parses a Node-version-sensitive display format. Lifecycle/parallel writer/adversarial input tests are missing. Use an explicit TAP reporter, propagate subprocess failure, and require real supported-version Loader tests. The bundled MCP server also advertises stale version 0.2.0.
- **Operational scripts:** Windows scripts restart matching DSH processes, use an unpinned `npx` launch, and include legacy Host-source patching. They were inspected statically, never executed. Replace the supported deployment path with pinned artifacts and explicit profile operations; a planning task does not authorize stopping the user's server.

## Coverage and remaining work

Inspected Host entry/tool definitions, storage/search/parser, standalone MCP, settings backend and Client form, HTML renderer, package exports/bundle, test wiring, release script, and deployment-script operations. The HTML renderer escapes embedded `<` and rendered fields; no demonstrated script injection was found in that renderer. This does not establish complete browser security.

The local target's `assembleContextFor` passes the Agent as both `agent` and `scope`; upstream's scope lookup therefore works for that path. It was not reported as a compatibility defect merely because `ScopeKey` is opaque. Import and schema compilation succeeded, but dependency activation, policy composition, complete real Loader use/unload, artifact installation, Windows support, power-loss recovery, and real-model quality remain unverified.

The fix sequence and complete learning feature are specified in the [implementation plan](../IMPLEMENTATION_PLAN.md). Keep baseline audit references pinned when subsequent fixes change line numbers.
